# DESIGN — จำลองการลงบัญชีระหว่างกรอก (Live Posting Simulation)

> ข้อกำหนดเพิ่มจากเจ้าของระบบ (2026-11-25): ทุกฟอร์มที่ทำให้เกิดการลงบัญชี ต้องแสดง
> **"บัญชีจะออกมาเป็นยังไง"** แบบ real-time ระหว่างที่ผู้ใช้กรอก ก่อนกดบันทึก/post
>
> ใช้คู่กับ [PHASE0-1_SPEC.md](PHASE0-1_SPEC.md) และ [PHASE2-3_SPEC.md](PHASE2-3_SPEC.md)

## 1. สิ่งที่ผู้ใช้เห็น (ฉบับปรับ 2026-11-25 ตามที่เจ้าของเลือก)

### เลย์เอาต์

- **Desktop (≥ md):** ฟอร์มซ้าย | แผงจำลองขวา (sticky ตามการเลื่อน)
- **มือถือ:** แผงจำลองเป็น **แถบล่าง (bottom sheet)** ติดใต้จอ
  - ตอนพับ: แถบเดียว "จำลองบัญชี · สมดุล ✓ · สรุปผลกระทบหลัก" (เช่น "ลูกหนี้ +10,700.00")
  - แตะเพื่อขยาย: แสดงคำอธิบายภาษาคน + ตาราง/T-account (ส่วน "ขั้นถัดไป" ซ่อนบนมือถือเพื่อประหยัดพื้นที่ แตะดูได้)
  - ไม่บังปุ่มบันทึก; เคารพ safe area ของ iOS

### เนื้อหาแผงจำลอง (เรียงจากบนลงล่าง)

1. **ป้ายสถานะ** "สมดุล ✓" / "ไม่สมดุล (ต่าง x.xx)"
2. **คำอธิบายภาษาคน (Plain-language)** — 1 บรรทัดต่อบัญชีที่ถูกกระทบ สำหรับคนที่ไม่ใช่นักบัญชี เช่น
   - "ลูกค้าค้างจ่ายคุณเพิ่ม 10,700.00"
   - "รายได้เพิ่ม 10,000.00 (กำไรเพิ่มเท่านี้)"
   - "ภาษีขายที่ต้องนำส่งสรรพากรเพิ่ม 700.00"
   - "ถูกหักภาษี ณ ที่จ่าย 300.00 (เครดิตภาษีตอนยื่นภาษีเงินได้)"
   - ข้อความผูกกับ **บทบาทบัญชี (account role) + ฝั่ง Dr/Cr** ไม่ผูกกับรหัสบัญชี → บัญชีที่ผู้ใช้เพิ่มเองใช้ข้อความทั่วไปตามประเภทบัญชี (เช่น "ค่าใช้จ่ายเพิ่ม …")
   - ข้อความอยู่ใน i18n (th/en)
3. **มุมมองบัญชี — สลับได้ 2 แบบ** (จำค่าที่ผู้ใช้เลือกไว้ใน localStorage)
   - **รายการบัญชี (Journal):** ตาราง รหัส/ชื่อบัญชี | เดบิต | เครดิต + แถวรวม; แตะแถวเพื่อดูที่มา เช่น "ภาษีขาย 7% ของ 10,000.00"
   - **T-account:** การ์ดต่อบัญชี ฝั่ง Dr | Cr แสดง "ยกมา" (ยอดปัจจุบัน) + "เอกสารนี้" (ไฮไลต์) + "คงเหลือ" ด้านล่าง → แทนส่วน "ผลกระทบต่อยอดคงเหลือ" ของดีไซน์เดิม
4. **ขั้นตอนถัดไป** (ถ้ามี) — เช่น ใบแจ้งหนี้ → "เมื่อรับชำระ" แสดงคำอธิบายภาษาคน + มุมมองเดียวกับข้อ 3

บัญชีทั้งหมดมาจาก `account_mappings` ของบริษัท (ไม่ hardcode) → ถ้า mapping ไม่ครบ แสดงคำเตือนพร้อมลิงก์ไปหน้า "การผูกบัญชี"

### กฎการแสดงผล

- อัปเดตทันทีเมื่อแก้ field ใดๆ (debounce ~300ms สำหรับการเรียก DB)
- ยอดยกมาใน T-account = ยอดคงเหลือ ณ วันที่ของเอกสาร (จาก journal ที่ post แล้ว) — มาพร้อมผล `simulate_posting`
- เอกสารที่ไม่ลงบัญชี (ใบเสนอราคา, ใบสั่งซื้อ) แสดง "เอกสารนี้ยังไม่ลงบัญชี" + ตัวอย่างบัญชีของขั้นตอนถัดไป
- บริษัทที่ไม่จด VAT ไม่แสดงแถว VAT
- ข้อผิดพลาด (เช่น ยังไม่เลือกลูกค้า, ไม่มี mapping) แสดงในแผงแทนตัวเลข ไม่ทำให้ฟอร์มพัง

## 2. สถาปัตยกรรม — "เครื่องเดียว ใช้สองแบบ"

**ตัวจำลองต้องให้ผลเหมือนการ post จริงทุกสตางค์** จึงห้ามเขียนกฎลงบัญชีซ้ำฝั่ง client

```
                ┌──────────────────────────────────────────┐
  ฟอร์ม (draft)  │ private.build_journal(company_id, doc)   │  ← กฎลงบัญชีอยู่ที่เดียว
  ─────────────►│  คืนค่า journal lines (ไม่เขียน DB)        │
                └──────────────┬───────────────┬───────────┘
                               │               │
        public.simulate_posting(doc jsonb)   public.post_document(id)
        (read-only, เรียกระหว่างกรอก)          (เขียน journal + เลขเอกสาร + audit log)
```

- **M4** สร้าง `private.build_journal()` เป็นฟังก์ชัน pure (รับข้อมูลเอกสาร → คืนรายการบัญชี)
  - `post_document()` เรียก `build_journal()` แล้วบันทึก
  - `simulate_posting()` เรียก `build_journal()` แล้วคืนผล + ยอดคงเหลือก่อน/หลัง โดย **ไม่เขียนอะไรเลย**
  - test: ทุกแถวของ posting rules ต้องยืนยันว่า `simulate_posting(x)` = journal ที่ `post_document(x)` สร้างจริง
- ฝั่ง client คำนวณได้เองเฉพาะ **ยอดรวมของฟอร์ม** (subtotal, VAT, WHT, ยอดสุทธิ) เพื่อความลื่น — ตัวเลขชุดนี้
  ต้องตรงกับ DB ด้วย test ชุดเดียวกัน (fixtures ร่วม `src/lib/money/*.test.ts` ↔ pgTAP)
- แผงจำลองเรียก `simulate_posting` ผ่าน TanStack Query (debounce, ยกเลิก request เก่าอัตโนมัติ)
- Component ใช้ร่วมทุกฟอร์ม: `<PostingPreview doc={...} />` (ภายในมี `<PlainSummary>`, `<JournalView>`, `<TAccountView>`, และ `<PreviewSheet>` สำหรับมือถือ)
- `simulate_posting` คืน: journal lines (+ account role, ที่มาของแต่ละแถว) และยอดยกมาของแต่ละบัญชี

## 3. ใช้ที่ไหนบ้าง

| Milestone | ฟอร์ม/หน้าจอ                                        | สิ่งที่จำลอง                                             |
| --------- | ------------------------------------------------- | ---------------------------------------------------- |
| M4        | (engine)                                          | `build_journal`, `simulate_posting` + tests          |
| M5        | ใบแจ้งหนี้, ใบกำกับ/ใบเสร็จ, ขายสด, ใบลด/เพิ่มหนี้, รับชำระ | journal + ผลกระทบลูกหนี้/รายได้/ภาษีขาย + ขั้นถัดไป (รับชำระ) |
| M6        | บันทึกค่าใช้จ่าย (เชื่อ/สด), จ่ายชำระ                     | journal + ผลกระทบเจ้าหนี้/ภาษีซื้อ/หัก ณ ที่จ่ายค้างจ่าย         |
| M7        | สมุดรายวันทั่วไป                                      | ยอดรวม Dr/Cr สด + ผลกระทบยอดคงเหลือ                   |
| M12       | สร้างเอกสารจากรายการ statement                     | journal ของเอกสารที่จะสร้าง                             |
| M13       | ขาย/ซื้อสินค้านับสต็อก, ปรับสต็อก                         | รวมแถวต้นทุนขาย/สินค้าคงเหลือ (FIFO/ถัวเฉลี่ย)               |
| M14       | ลงค่าเสื่อม, ขาย/ตัดจำหน่ายสินทรัพย์                      | journal ค่าเสื่อม, กำไร/ขาดทุนจากการจำหน่าย               |
| M15       | ปิดปีบัญชี                                            | journal โอนกำไรขาดทุนเข้ากำไรสะสม ก่อนยืนยัน              |
| M20       | คิวตรวจทาน OCR                                     | แผงจำลองอยู่ข้างฟอร์ม → เห็นบัญชีก่อนกด "ยืนยันและบันทึก"        |
| M22       | Auto-post                                         | เก็บผลจำลองไว้กับเอกสาร เพื่อตรวจย้อนหลังได้                 |

## 4. ตัวอย่าง (ใบแจ้งหนี้ขายเชื่อ บริษัทจด VAT)

กรอก: บริการ 1 รายการ 10,000.00, แยก VAT 7%, ลูกค้าจะหัก ณ ที่จ่าย 3% ตอนจ่าย

|                | บัญชี                      |      เดบิต |     เครดิต |
| -------------- | ------------------------ | --------: | --------: |
| ใบแจ้งหนี้        | 1130 ลูกหนี้การค้า           | 10,700.00 |           |
|                | 4100 รายได้จากการให้บริการ  |           | 10,000.00 |
|                | 2120 ภาษีขาย              |           |    700.00 |
| ขั้นถัดไป: รับชำระ | 1120 เงินฝากธนาคาร        | 10,400.00 |           |
|                | 1150 ภาษีเงินได้ถูกหัก ณ ที่จ่าย |    300.00 |           |
|                | 1130 ลูกหนี้การค้า           |           | 10,700.00 |

(ตัวเลขตาม posting rules ใน PHASE0-1_SPEC ข้อ 2 — ยังรอคำตอบเรื่อง "ภาษีขายยังไม่ถึงกำหนด" สำหรับธุรกิจบริการ ซึ่งจะเปลี่ยนแถวภาษีขายในตัวอย่างนี้)
